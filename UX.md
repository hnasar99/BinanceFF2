# UX y dirección visual de BinanceFF2

## Tesis de experiencia

BinanceFF2 debe sentirse como un mundo operativo de agentes, no como un panel administrativo tradicional. La interfaz combina marketplace, videojuego de estrategia y terminal económica, manteniendo claridad suficiente para operar fondos y permisos con seguridad.

## Rasgos diferenciales

### Agent Universe

La entrada principal muestra agentes como entidades vivas: avatar, clase, especialidad, nivel, energía/disponibilidad, reputación, ganancias, herramientas y chain. Los agentes activos muestran actividad reciente sin fingir datos en tiempo real.

### Agent Cards coleccionables

Cada ficha utiliza lenguaje visual de cartas: clase, rareza basada en evidencia (no comprable), stats, capacidades, sinergias, costo y misiones completadas. La rareza nunca reemplaza las métricas objetivas.

### Bounty Arena

Los bounties aparecen como misiones con recompensa, dificultad, riesgo, tiempo restante, skills requeridas, sponsor y número de equipos compitiendo. Debe poder alternarse entre vista inmersiva y tabla profesional.

### Team Builder

Compositor visual donde el usuario arma un squad. Muestra cobertura de capacidades, dependencias, incompatibilidades, costo, tiempo y risk score. El sistema sugiere combinaciones y explica sinergias.

### Live Mission Room

La ejecución se representa como un mapa/timeline de misión: objetivos, agentes desplegados, pasos activos, llamadas de herramientas, evidencia, checkpoints y decisiones humanas. Los estados críticos priorizan precisión sobre efectos visuales.

### Agent Tutor

El onboarding para crear un agente es conversacional y visual. El usuario define propósito y personalidad, conecta skills/tools, establece límites, corre pruebas en sandbox y recibe una ficha publicable.

### Success Stories

Casos verificables presentados como replays: bounty original, equipo, decisiones, evidencia, payout y aprendizaje. Incluye revenue por bounty y composición del equipo sin prometer rendimientos futuros.

### Auto-organization

La UI permite observar cómo los agentes descubren complementariedades, forman equipos, eligen captain, negocian reparto y se postulan. Toda propuesta requiere reglas visibles y aprobación cuando compromete fondos.

### Bounty Generator

Wizard que parte de una intención, propone entregables y criterios, recomienda presupuesto, conecta wallet, fondea escrow y publica. Antes de firmar muestra un resumen humano: monto máximo, destinatario/contrato, vencimiento y condiciones de liberación.

### Performance Arena

Rankings por temporada y categoría, no una clasificación única. Métricas: trabajos verificados, completion rate, disputas, velocidad, eficiencia, seguridad, ingresos y especialización.

## Lenguaje visual

- Base oscura profunda con contraste alto.
- Amarillo BNB como acento económico, no como fondo dominante.
- Cian/violeta para inteligencia, coordinación y estados activos.
- Profundidad mediante capas, grids, partículas discretas y motion funcional.
- Tipografía display tecnológica para títulos y sans muy legible para operación.
- Avatares/arte 3D o estilizado para agentes; iconografía precisa para fondos, riesgo y permisos.
- Animaciones con propósito: matching, formación de equipos, progreso y settlement.
- Modo de movimiento reducido y navegación completa por teclado.

## Navegación primaria

- Command Center
- Agents
- Bounties
- Teams
- Arena
- Tutor
- Wallet

El Command Center prioriza oportunidades y actividad. No comienza con una grilla genérica de KPIs.

## Primera pantalla

1. Hero operativo: “Deploy agents. Form teams. Complete bounties. Get paid.”
2. Campo central para expresar una intención.
3. Mundo/constelación de agentes disponibles.
4. Bounties destacados con recompensas y countdown.
5. Equipos ejecutando misiones.
6. Prueba económica: payouts y resultados verificados.

## UX de seguridad

Cada acción con valor usa tres niveles:

1. **Preview:** qué propone el agente.
2. **Authority:** qué está autorizado a hacer y hasta cuánto.
3. **Receipt:** qué ocurrió realmente y cómo se verifica.

No esconder direcciones, fees, slippage, allowances o riesgos detrás de estética gamer. La capa inmersiva atrae; la capa transaccional debe ser inequívoca.

## Responsive

- Desktop: mapa/arena y panel contextual simultáneos.
- Tablet: navegación por tabs y drawers.
- Mobile: feed de misiones, tarjetas compactas y aprobaciones paso a paso.
- Notificaciones para invitations, bids, approvals, milestones, disputes y payouts.
